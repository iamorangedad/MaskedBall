# 上线前还缺的模块

历史记录。写于 2026-09-30，依据当时的 `web/server.py` 与 `web/static`。网页那时能在本机演示，还不能当作对陌生人开放的服务。后来账号、SQLite、访问边界和模型队列已经按这份评估落地；下文保留评估当时的判断，不代表现在的实现。

来源：[上线评估](/home/jetson/.cursor/projects/home-jetson-MaskedBall/canvases/launch-readiness.canvas.tsx)

## 现在怎么工作

**聊天存在一个 JSON 文件里。** 全部用户、画像和消息写在 `web/data/space.json`。每次发消息都把整个文件重写一遍。进程停掉或文件损坏，记录就一起没了。没有备份，也没有按会话拆开的数据库。

**没有注册。** 进入舞会只提交一个显示名。服务生成 `guest-` 开头的编号，放进浏览器 Cookie `mb_id`，有效期一年。Cookie 的值就是用户编号本身，没有密码、邮箱或签名。知道这个编号的人可以冒充该用户。

空间里的林晚、阿禾等人是写在代码里的常驻角色，由本机 Ollama 的 `qwen3:4b` 代答，不是注册用户。

## 上线要补的模块

优先级按公开给陌生人使用来排。先做的六项缺一不可。

| 模块 | 现在 | 上线需要 | 顺序 |
| --- | --- | --- | --- |
| 账号 | 只填名字，Cookie 即身份 | 注册、登录、可撤销的签名会话、退出和找回 | 先做 |
| 聊天存储 | 单个 `space.json`，整文件重写 | 数据库保存用户、画像、会话和消息，并做备份 | 先做 |
| 访问边界 | 画像和背景对空间里所有人可见 | 聊天记录只给会话双方；公开名片和代聊上下文分开 | 先做 |
| 两个真人对话 | 对方选亲手回复时，消息只是存着，要重新打开才看得到 | 在线推送、未读、离线后仍能接到 | 先做 |
| 部署 | 默认只听 `127.0.0.1:8787` | HTTPS、公网入口、进程守护、证书 | 先做 |
| 模型服务 | 发消息的请求里同步调用本机模型 | 独立推理进程、队列、超时和每人限额 | 先做 |
| 安全与审核 | 没有举报、拉黑或内容边界 | 拉黑、举报，以及代聊不能替用户承诺或索取敏感信息 | 接着做 |
| 在场 | 看不出对方是不是真的在 | 在线、离开，以及亲手回复时的等待状态 | 接着做 |
| 空间规模 | 所有人画在同一张图上，搜索在浏览器里完成 | 服务端搜索、分页，人多时只显示有关系的人和附近的人 | 以后 |

## 建议的落地顺序

先把身份和数据库换上，再让两个登录用户的消息能实时送达。模型调用从网页请求里拆出去，并加上 HTTPS。审核和在场状态可以跟第一批真实用户一起补。人一多，再改空间的发现方式。
